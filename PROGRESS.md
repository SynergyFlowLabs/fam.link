- **2026-10-22 — Canvas bug fix (user-reported: drag blanks the tree) + edge redesign (user-requested: smoother relationship lines):** **Root cause** of the blank-canvas drag: `onPointerMove` computed the vertical pan factor as `view.w * aspect` (the *entire world height*) instead of world-units-per-pixel, so ~1px of vertical drag jumped a full viewport — the tree flew off-screen (horizontal was correct, hence the intermittent feel). Fix: one uniform `scale = view.w / rect.width` for both axes (the viewBox aspect matches the element exactly via ResizeObserver), `rect.width > 0` guard. **Hardening:** `setPointerCapture` on `e.currentTarget` (was `e.target`, could capture a child), `endDrag` now resets `dragging` state (cursor no longer sticks on "grabbing"), and pan is **clamped to content bounds** (node bbox + 480px pad, memoized) — dragging can never leave the canvas blank again. **Edge redesign:** replaced ad-hoc couple lines + cubic S-curves with a pure geometry module `src/lib/layout/edges.ts` — couples: straight with 3-unit inset (or soft S-curve across rows, sag ≤ 42); parent-child: classic genealogy **orthogonal bus** — vertical drop off the marriage line (T-junction), rounded corner (r ≤ 14, clamped to available space), shared horizontal bus at 45% of the gap, corner, drop to the child; plain elbow when tight, straight when aligned. Siblings of one union are collinear on the same bus. Round linecaps/joins, 0.55 opacity. 9 new unit tests (34 total): bus collinearity, mirrored children, radius clamping, degenerate cases. Verified: build/lint/tsc green; rendered canvas audited — 0 cubic S-curves remain, sibling drops share busY, rounded corners present.
